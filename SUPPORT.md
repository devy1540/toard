# Support

toard is maintained on a best-effort basis and does not provide a response-time SLA or private deployment support.

## Usage and deployment questions

Use [GitHub Discussions Q&A](https://github.com/devy1540/toard/discussions/categories/q-a) for installation, configuration, upgrades, and general troubleshooting. Before posting, remove tokens, credentials, private prompts, customer data, internal hostnames, and unsanitized logs.

## Bugs and feature proposals

- Use the [bug report form](https://github.com/devy1540/toard/issues/new?template=bug_report.yml) for a reproducible defect.
- Use the [feature request form](https://github.com/devy1540/toard/issues/new?template=feature_request.yml) for a scoped improvement.
- Search existing issues and discussions before opening a new one.

Include the toard version or commit, deployment method, storage backend, authentication mode, expected behavior, actual behavior, and a minimal reproduction when available.

## Security vulnerabilities

Do not report vulnerabilities publicly. Follow [SECURITY.md](SECURITY.md) and use the repository's [private vulnerability reporting](https://github.com/devy1540/toard/security/advisories/new).

## Data recovery and production incidents

Maintainers cannot access self-hosted installations or recover deleted databases, keys, Recovery Kits, credentials, or local session files. Preserve logs and backups without posting secrets, and follow the relevant runbook under `docs/`.
