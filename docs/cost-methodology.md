# 비용 계산과 해석

toard의 금액은 관측한 사용량에 API 토큰 요율을 적용한 **환산 추정액**이다.
구독료, 포함 사용량, 계약 할인, 세금, 도구 부가 요금 및 실제 청구 내역을 대조한 금액이 아니다.

## 계산 규칙

현재 규칙은 `cost-v2`다. 입력 컨텍스트는 신규 입력 + 캐시 읽기 + 캐시 생성 토큰으로 계산한다.
컨텍스트 구간이 달라지면 해당 구간의 단가를 전체 입력과 출력에 적용한다. 초과분에만
높은 단가를 붙이거나 출력 토큰 수로 출력 구간을 별도 판정하지 않는다.

- 가격 이력에는 LiteLLM의 128k, 200k, 256k, 272k, 512k 등 컨텍스트 구간과 캐시 단가를 보존한다.
- 입력·출력·캐시 읽기·캐시 생성·1시간 캐시 생성의 비용을 각각 계산한다.
- 공급자별 캐시 요율이 없을 때 다른 공급자의 요율을 임의 적용하지 않는다. 문서화된 Claude/Gemini fallback 이외에는 미확정으로 둔다.
- GPT-5.4/5.5처럼 공식 과금 조건이 세션 전체에 적용되지만 로그에서 개별 요청만 확인된 경우 `estimated`로 표시한다.
- 모델 별칭을 추정하거나 캐시 보존 시간을 가정한 경우도 추정 상태로 표시한다.

검증 사례(2026-09-06 확인):

| 입력 | 공식 요율 계산 | 회귀 검증 |
|---|---|---|
| Gemini 2.5 Pro: 신규 입력 300,000, 출력 10,000, 캐시 없음 | 0.3×$2.50 + 0.01×$15 = $0.90 | 기존 $0.60 누진 계산 방지 |
| Gemini 2.5 Pro: 신규 입력 100,000, 캐시 읽기 201,000, 출력 10,000 | 0.1×$2.50 + 0.201×$0.25 + 0.01×$15 = $0.45025 | 캐시를 컨텍스트 기준과 캐시 요율에 모두 반영 |
| GPT-5.4: 신규 입력 300,000, 출력 10,000 | 개별 요청 환산 $1.725 | 272k 구간 보존, 세션 정보 부족 시 estimated |

근거: [Gemini 공식 요금표](https://ai.google.dev/gemini-api/docs/pricing#gemini-2.5-pro),
[GPT-5.4 공식 요금표](https://developers.openai.com/api/docs/models/gpt-5.4),
[Claude 공식 요금표](https://platform.claude.com/docs/en/about-claude/pricing),
[LiteLLM 필드 정의](https://github.com/BerriAI/litellm/blob/main/model_prices_and_context_window.json).

## 상태

| 내부 상태 | 제품 의미 |
|---|---|
| `priced` | 모델/요율을 확인한 API 환산액. 실제 청구액 확인을 뜻하지 않는다. |
| `estimated` | 모델, 캐시 시간, 세션 범위 등 일부 조건을 추정한 환산액. 합계에 포함하되 별도 표시한다. |
| `unpriced` | 계산 근거 부족. 금액 합계에서 제외하고 부분 합계로 표시한다. |
| `legacy` | 과거 가격 확정 경로에서 생성된 값. |

계산 버전과 가격 상태는 별도다. 과거 행에는 `cost-v1`을 기록하고 저장 금액을 그대로 보존한다.
이 마이그레이션은 과거 금액을 새 계산 결과처럼 덮어쓰지 않는다. 수정된 규칙은 신규 수집과
이후 실행되는 기존 가격 복구 작업에 적용한다. 기존 복구 대상이 아닌 과거 `priced` 행이
자동으로 모두 재계산되는 것은 아니다.

## 가격 이력과 계산 근거

가격은 이벤트 발생 시각에 유효한 revision으로 선택한다. 당일 단가나 부가 요율이 바뀌어도
기존 revision을 수정하지 않고 가격 내용 fingerprint가 다른 revision을 추가한다.
새 이벤트에는 계산 버전, 가격 revision, 수집된 1시간 캐시·속도 힌트를 함께 저장한다.

대시보드의 **내 비용 계산 내역**(`/costs`)은 로그인 사용자 범위의 보존 중인 사용 이벤트를
50건씩 조회한다. 콘텐츠 히스토리를 켜지 않아도 사용할 수 있으며 프롬프트·코드 본문을 조회하지 않는다.
가격 출처·적용일·모델·규칙 버전·토큰을 확인할 수 있고, 재현한 금액이 저장 금액과 일치하는
`cost-v2` 기록만 항목별 계산을 보여준다. 원본이 보존되지 않는 오래된 rollup은 개별 계산 근거를 제공할 수 없다.

## 업그레이드와 운영

- 마이그레이션 `1700000054`를 앱 교체 전에 적용한다. 기존 행은 보존하며 rollback SQL로 근거를 삭제하지 않는다.
- 과거 seed.ts의 임시 요율은 새 계산에서 제외한다. 새 seed는 임의 가격을 넣지 않는다.
- production은 기본 내장 가격 동기화가 실행된다. 로컬 개발에서는 `PRICING_AUTO_SYNC=on pnpm dev`로 켠다. 관리자 가격 화면은 동기화 상태를 읽기 전용으로 보여준다.
- 가격 소스가 일시적으로 실패해도 사용량은 미확정 상태로 보존되고 복구 작업이 가격표를 다시 확인한다.
- 과거 금액과 재계산 결과를 비교할 때 계산 버전과 필요한 입력 힌트의 보존 여부를 함께 확인한다.

```sh
pnpm --filter @toard/pricing test
TSX_TSCONFIG_PATH=apps/web/tsconfig.json node --import tsx --test scripts/pricing-calculation.integration.test.ts scripts/pricing-clickhouse.integration.test.ts
```
