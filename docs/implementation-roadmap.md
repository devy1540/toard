# toard 신뢰성 및 제품 개선 실행 계획

기준: 2026-09-06. 사용자가 분석에서 제안한 개발 순서 전체의 구현을 요청했다. 운영 DB나 실제 사용자 원본 로그 대신 격리한 합성 데이터로 검증한다. 현재 릴리스 후보는 **0.0.3**, schema 기준은 **1700000055**다.

## 1. 가입, 비용, 첫 진입

- [x] 가입 기본값을 invite-only로 변경. 이메일 문자열만으로 가입하지 않고 기존 로그인·최초 관리자 설치를 보존한다.
- [x] 공개 가입은 검증된 OAuth identity로 제한하고 초대 수락·팀 배정은 원자 처리한다.
- [x] 임의 팀 self-selection을 제거하고 관리자 배정만 적용한다.
- [x] 요청 문맥 기준 단가·캐시·출력 비용을 공식 가격 사례로 검증한다.
- [x] API 환산액, 모델 추정, 미확정 비용을 구분한다. 계산 버전과 가격 근거를 보존하며 과거 값을 새 계산이라고 표시하지 않는다.
- [x] 랜딩과 정적 데모 진입 코드를 복구하고 합성 데이터 화면을 제공한다.

## 2. 수집 신뢰성과 통제

- [x] 연결 성공과 실제 사용량 저장 완료를 분리한다.
- [x] 공급자별 저장·읽기/파싱 오류·미지원·새 기록 없음·일시 중지를 구분한다.
- [x] 서버별 도구·프로젝트 포함/제외와 로컬 미리보기·승인을 제공한다.
- [x] 크기 제한 영속 큐, 저장 확인 이후 정리, 장애·재시도·중복·원본 삭제 복구를 검증한다.
- [x] 실제 브라우저에서 가입·권한·수집 완료·비용 표시를 검증하는 CI를 추가한다.

구현 경계는 [수집 신뢰성](collection-reliability.md)과 [수집 범위](collection-scope-implementation.md)에 기록했다. 설정용 프로젝트 목록·경로는 로컬에 유지한다. 미식별 프로젝트는 제한 모드에서 차단하며, 이미 실행 중인 외부 AI 프로세스를 강제로 종료하지 않는다.

## 3. 판단에 도움이 되는 분석과 보고

- [x] 사용량·모델 구성·입출력·캐시·실효 단가의 기여를 합계와 일치하게 분해하고 근거 부족을 구분한다.
- [x] 완료된 주의 개인·권한 있는 팀/조직 보고서와 CSV에 변화·수집 상태·가격 근거를 제공한다.
- [x] 계산·운영·업그레이드 문서와 관련 검증을 갱신한다.
- [x] 3~5개 외부 팀 파일럿을 위한 설치·피드백·초대문 초안과 성공/중단 기준을 준비한다.
- [ ] 실제 외부 팀의 2주 반복 사용을 검증한다. 외부 연락·데이터·접근 권한이 필요하며 임의 결과를 작성하지 않는다.

[주간 보고서](weekly-reports.md), [업그레이드](trust-roadmap-upgrade.md), [파일럿 운영안](pilot/README.md)을 참고한다.

## 검증 기록

- 가입·가격 단계: 전체 Node 검사 1,332 통과, PostgreSQL/ClickHouse 가격 근거 통합 검증 및 브라우저 6개 시나리오 통과.
- 수집 단계: 전체 Node/DB 검사 1,346 통과·3 skip, Rust 전체 287 통과·1 ignored 이후 추가 CLI 사례도 통과. 최종 CLI 4개는 실제 curl/loopback HTTP를 사용했다.
- 수집 범위 브라우저 9개 시나리오 및 후속 확인창 준비/배치 변경 검증 통과. 관리자·일반 사용자·로컬 scope 테스트 계정은 서로 분리했다.
- 보고서 단계: 각 변화 요인의 독립 사례·혼합 합계·기간 반전·미확정 가격 오해 방지 검증. 실제 PostgreSQL 2,003개 기록, pool 크기 1, 조회 중 insert 및 실패 후 connection 반환을 확인했다.
- ClickHouse 보고서는 한 번의 FINAL stream을 사용하며 변경 전 팀 row가 노출되지 않는지 실제 DB로 확인했다. 스트림 처리 후 overload 재시도로 이중 집계하지 않도록 했다.
- 실제 보고서 브라우저에서 로그인·개인/팀/조직 권한·CSV 수식 처리·미확정 금액·모바일 너비를 검증했다.
- 최종 Node/DB 1,366 pass · 3 skip · 0 fail, 실제 브라우저 11개 시나리오 통과. 후속 소규모 방어 변경은 관련 17개 단위 검사와 typecheck로 확인했다. 0.0.3 버전/스키마 정합성과 Kubernetes manifest·Secret helper 검증도 통과했다. 최초 실패는 원인을 수정한 뒤 관련 검사를 다시 실행했다.
