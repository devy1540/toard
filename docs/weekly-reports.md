# 주간 보고서와 비용 변화 분석

주간 보고서는 완료된 일요일~토요일의 **수집 기록**을 직전 주와 비교한다. 개인은 본인 기록, 팀 리더는 본인 팀, 관리자는 조직과 각 팀을 조회한다. 팀 귀속은 이벤트 발생 당시의 `team_id`를 사용한다. 개인 보고서는 뷰어 타임존, 팀·조직 보고서는 `ORG_TIMEZONE`을 기준으로 한다.

상세 가격 근거가 필요한 보고서이므로 비교 기간 전체가 90일 논리 보존 범위 안에 있어야 한다. 이번 주의 일부를 지난주의 전체와 비교하거나, 보존 기간 밖의 누락을 0으로 표시하지 않는다. 장기 rollup 조회와 상세 주간 보고서의 조회 범위는 다르다.

## 금액의 의미

여기서 금액은 저장된 사용량을 API 요율로 환산한 값이다. 구독료·크레딧·계약 할인·실제 청구서를 집계한 값은 아니다. 미확정 기록의 가격을 0이라고 가정하지 않으며, ClickHouse에 반영 중인 outbox 기록이 있으면 합계가 불완전하다고 표시한다.

개별 기록의 계산 버전·가격 revision·힌트로 저장 금액을 재현할 수 있어야 요인 분해에 사용한다. 어느 한 주라도 해당 도구/모델의 가격이나 계산 근거가 부족하면 **그 모델군을 양쪽 주 모두** 분해에서 제외한다. 가격을 잃은 모델의 환산액 감소를 사용량 감소나 절감으로 설명하지 않기 위해서다. 남은 저장 금액 차이는 미분류에 표시한다.

## 다섯 요인

| 요인 | 의미 |
|---|---|
| 사용량 규모 | 분해 대상의 전체 토큰 수 변화 |
| 모델 구성 | 도구/모델별 토큰 비중 변화 |
| 입력·출력 비중 | 모델 내 입력과 출력의 비중 변화 |
| 입력 캐시 구성 | 입력 중 일반 입력, cache read, 5분/1시간 cache write의 비중 변화 |
| 실효 단가·과금 조건 | 각 토큰 종류의 관측된 평균 단가 변화 |

금액은 `전체 토큰 × 모델 비중 × 모델별 입출력·캐시 구성 × 실효 단가`로 재현한다. 다섯 요인을 적용하는 120가지 순서에서 각 요인의 기여를 평균한다(Shapley 분해). 이는 관측된 구성의 산술 분해이며 원인과 결과의 인과관계를 입증하지 않는다.

실효 단가에는 가격 revision 외에 긴 문맥 tier와 fast 모드 같은 요청 조건도 들어간다. 따라서 이 항목을 공급자의 가격 인상액으로 해석하면 안 된다. 어느 주에 관측되지 않은 모델·토큰 종류에는 다른 주에서 관측한 구성/단가를 사용한다. 관측하지 못한 가격 변화를 만들어 내지 않는다.

SQL 소수점 반올림은 기록별 구성 비용을 저장 금액에 맞춰 보정한다. 화면은 여섯 자리까지 표시하며, 미분류·반올림 항목을 포함한 표시 합계가 표시된 전체 차이와 일치한다. 미확정 기록 때문에 합계에 들어가지 않은 금액은 숫자로 추정하지 않는다.

## 조회와 권한

PostgreSQL은 읽기 전용 repeatable-read cursor, ClickHouse는 한 번의 `FINAL` 조회를 순차 처리한다. 100개나 1,000개 상위 기록만으로 보고서를 만들지 않는다. SQL에서 권한 범위를 적용하고, 보고서 스트림에는 세션 ID·컴퓨터 이름·대화 본문을 포함하지 않는다. 가격 metadata는 cursor를 점유하기 전에 가져와 connection pool이 하나인 구성에서도 교착되지 않는다.

스트림 소비 뒤에는 자동 재시도를 하지 않는다. 일부 기록을 처리한 후 같은 스트림을 재시도해 이중 집계하는 것을 막는다. 실패한 보고서는 완성된 CSV로 반환하지 않는다.

보고서는 최대 10분 캐시되며 설치 식별자·조회 범위·타임존·공유 mutation generation으로 구분된다. 수집/보정이 진행 중이면 캐시를 우회해 조회한다. 수집 상태 표는 생성 당시 주간 장애 이력이 아니라 **현재 연결의 상태**다. 프로젝트 범위 변경과 누락이 실제 사용량 변화에 얼마나 기여했는지는 이 데이터만으로 확인할 수 없다.

## CSV

`GET /api/reports/weekly?week=YYYY-MM-DD&scope=personal`은 동일 권한 검증을 거쳐 CSV를 반환한다. 팀은 `scope=team:<id>`, 조직은 `scope=organization`을 사용한다. 요청의 임의 `userId`로 타인의 기록을 선택할 수 없다.

CSV에는 주간 합계, 모델 비교, 요인별 기여, 계산 버전·가격 revision, 현재 수집 상태를 같은 열 구조로 담는다. 가격이 전혀 없는 모델의 금액과 비교 불가능한 차이는 빈 칸으로 둔다. 문자열의 수식 시작 문자·선행 제어문자는 작은따옴표를 붙여 spreadsheet formula injection을 방지한다. 음수 금액 변화는 문자열이 아닌 숫자로 유지한다.

## 검증 근거

- `cost-drivers.test.ts`: 각 요인만 바뀐 사례, 복합 변화, 기간 반전, 합계 일치, cache write subset, 미확정 가격을 절감으로 오인하지 않는 사례.
- `weekly-report.integration.test.ts`: 2,003개 기록, pool 크기 1, 조회 중 insert, 실패 후 connection 반환, 과거 팀 귀속, ClickHouse의 대체된 팀 row 제거.
- `reports.spec.ts`: 실제 로그인·개인/팀/조직 권한·CSV 다운로드·미확정 금액·모바일 표시.
